# 코잇다 화면 목록 v1

> 기준 문서: `요구사항정의서 v1.2`, `API목록 v2.2`, `ERD v1.2`, `서비스 프롬프트 v3`
> 산출물 순서: 요구사항 → 기능 → IA → **화면 목록** → 와이어프레임 → 스토리보드
> 총 78개 화면 (P0 45 / P1 28 / P2 5)

## 1. 문서의 목적

요구사항과 API가 **실제로 어느 화면에 붙는지** 확정한다. 이 단계를 건너뛰면 개발 중에 두 가지 문제가 생긴다.

- API는 만들었는데 호출할 화면이 없다
- 화면은 그렸는데 데이터를 가져올 API가 없다

그래서 이 문서의 마지막에 **양방향 검증 결과**를 넣었다.

## 2. 화면 ID 규칙

```
SCR-{도메인}-{일련번호}
예: SCR-PRJ-003 → 니팅로그 생성
```

운영 지침 6항의 추적 규칙에 따라 한 번 부여한 ID는 특별한 사유 없이 바꾸지 않는다.

| 코드 | 도메인 |
|---|---|
| `AUTH` | 인증·계정 |
| `HOME` | 홈·둘러보기 |
| `PTN` | 도안 |
| `ORD` | 주문·결제 |
| `LIB` | 구매 도안 |
| `PRJ` | 코잇기·니팅로그 |
| `POST` | 오늘의 로그 |
| `REV` | 도안 리뷰 |
| `GAU` | 게이지 계산 |
| `FREE` | 실타래 |
| `SOC` | 소셜 |
| `MY` | 마이페이지 |
| `SEL` | 판매자 |
| `ADM` | 관리자 |

## 3. 화면 유형

| 유형 | 정의 | 뒤로가기 |
|---|---|---|
| **페이지** | 고유 URL을 가지며 브라우저 히스토리에 남는다 | 이전 페이지 |
| **모달** | 현재 맥락 위에 뜨는 창. 배경 화면을 유지한다 | 모달 닫힘 |
| **시트** | 모바일에서 아래에서 올라오는 창 | 시트 닫힘 |
| **영역** | 페이지 안의 구획. 단독 진입 불가 | — |

모달과 시트는 같은 기능의 PC·모바일 대응으로 묶어서 하나의 ID를 쓴다.

**SCR-PRJ-003 화면 구성 순서**

```
1. 도안 연결        ← 필수. 3개 탭 (구매·판매·외부)
2. 제목            ← 선택. 미입력 시 날짜 기반 자동
3. 실·바늘·게이지    ← 가로형 행 추가 방식
4. 대표 이미지       ← 최대 7개
5. 비고
6. 공개 여부        ← 기본 비공개
```

도안 연결을 맨 위에 두는 이유는 **판매 도안을 고르면 원작 실·바늘·게이지가 자동으로 채워지기 때문**이다(PROJECT-017). 재료 입력보다 먼저 와야 한다.

**SCR-PRJ-012 확인 내용**

```
니팅로그를 비공개로 변경합니다.

· 공개 중인 오늘의 로그 3개가 함께 비공개가 됩니다.
· 이 니팅로그에서 작성한 도안 리뷰가 1개 있습니다.
  [ ] 리뷰는 공개 상태로 유지합니다.
```

**SCR-POST-001 ↔ SCR-POST-002 전환**

두 화면은 같은 데이터를 쓰는 **다른 작성 경험**이다(POST-002). 빠른 작성에 `상세하게 기록하기` 버튼을 두고, 누르면 작성 중인 내용을 유지한 채 블록 에디터로 전환한다. 저장 후에도 서로 전환 가능하다.

**SCR-POST-005 확인 내용**

```
이 니팅로그는 비공개입니다.
로그를 공개하면 니팅로그도 함께 공개됩니다.

[취소]  [로그만 비공개로 저장]  [함께 공개하기]
```

확인하지 않으면 로그를 비공개로 저장한다(POST-011).

**SCR-REV-001 구성**

```
리뷰 작성하기
├─ 기존 오늘의 로그 불러오기 → SCR-REV-002
└─ 새로 작성하기            → SCR-REV-003 (빈 화면)
```

**SCR-REV-003 저장 후 안내**

포인트 적립을 알려야 한다(POINT-001). "리뷰 작성으로 N포인트가 적립되었습니다."

**SCR-REV-006 확인 내용**

```
리뷰를 삭제합니다.

· 적립받은 N포인트가 회수됩니다.
· 삭제 후 이 도안에 리뷰를 다시 작성할 수 있습니다.
```

잔액 부족으로 회수가 불가능하면 안내 문구가 달라진다(POINT-003).

## 17. 핵심 화면 흐름 5개

### 흐름 1 — 도안 발견에서 니팅로그 시작까지 (P0)

```
SCR-HOME-001 → SCR-PTN-001 → SCR-PTN-003
                                  ├─ 구매 → SCR-ORD-001 → SCR-ORD-003 → SCR-LIB-001
                                  └─ 니팅로그 만들기 → SCR-PRJ-003 → SCR-PRJ-004/005/006
                                                                        ↓
                                                                   SCR-PRJ-007
```

### 흐름 2 — 제작 기록 (P0)

```
SCR-PRJ-007 → SCR-POST-001 (빠른 작성)
                  ├─ 상세하게 → SCR-POST-002
                  ├─ 대표 이미지 미설정 → SCR-POST-004
                  └─ 니팅로그 비공개 + 로그 공개 → SCR-POST-005
                                                      ↓
                                              SCR-PRJ-007 (상태·공개 갱신)
```

### 흐름 3 — 리뷰 작성과 포인트 (P1)

```
SCR-PTN-003 (보유 + 미작성)
    → SCR-REV-001 ─┬─ 로그 불러오기 → SCR-REV-002 → SCR-REV-003
                   └─ 새로 작성      → SCR-REV-003
                                          ↓
                                   포인트 적립 안내 → SCR-MY-003
```

### 흐름 4 — 도안 변경 인지 (P1)

```
판매자: SCR-SEL-004 → SCR-SEL-006 (변경 요약 입력)

       구매자 알림              니팅로그 변동사항
```

한 번의 입력이 두 경로로 갈라진다.

```
    → SCR-PRJ-012 (영향 확인)
```

### 요구사항 ID가 없는 화면 ⚠️

| 화면 | 문제 |
|---|---|
| SCR-GAU-001~003 | **게이지 계산 요구사항이 요구사항 정의서에 없다.** AI-001에 "계산은 프로그램이 수행한다"는 원칙만 있고 기능 요구사항이 없다 |
| SCR-SEL-002 (판매자 홈) | 판매자 대시보드 요구사항이 없다. `settlement-preview` API만 존재 |
| SCR-MY-002 (프로필 수정) | 프로필 수정 요구사항이 없다. `PATCH /users/me` API만 존재 |

**게이지 계산이 가장 큰 공백이다.** 서비스 프롬프트 12장에는 "게이지 계산과 통계는 코드로 처리한다"가 있고 MVP P1 범위에도 "게이지 계산과 AI 설명·추천"이 들어 있는데, 요구사항 정의서에는 `GAUGE-xxx` ID가 하나도 없다. 도안 게이지와 내 게이지를 어디서 입력받는지, 결과를 니팅로그에 저장하는지가 정의되지 않았다.

→ 요구사항 정의서 v1.3에 `GAUGE-001~005` 신설 필요.

### API가 없는 화면

없음. 모든 화면이 대응 API를 갖는다.

### 확인이 필요한 항목

| # | 항목 | 이유 |
|---|---|---|
| 1 | **게이지 계산 진입점** | 도안 상세? 니팅로그 상세? 독립 메뉴? 어디서 들어가는지 미정 |
| 2 | **계산 결과를 니팅로그에 저장할지** | 저장한다면 `PROJECT_GAUGE`에 넣을지 별도 컬럼일지 |

| 5 | **알림 진입점** | 헤더 벨 아이콘 + 목록 페이지 구조로 확정할지 |
