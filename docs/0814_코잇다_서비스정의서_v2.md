# 코잇다 서비스 정의서 v2

> 서비스 프롬프트 v3를 기반으로, 이후 실제 구현·확정된 사용자 경험과 정책을 통합한 최신 서비스 기준본이다.
> v1(서비스 프롬프트 v3) 이후 확정·구현된 **카카오 소셜 로그인, 개인정보 동의 단계, 도안 PDF 다중 등록·다운로드, 도안 문의하기, 도안 상세 블록 본문, 카테고리 트리 개편, 뜨개 방식 혼합(MIXED)**을 반영했다.

## 1. 서비스 정의

코잇다는 도안 탐색·구매, 실제 작품 계획, 제작 과정 기록, 완성 경험 공유를 **하나의 흐름으로 연결하는 뜨개 통합 플랫폼**이다.

핵심 경험은 **다른 사람의 실제 제작 정보가 다음 사용자의 선택과 시작을 돕는 순환**이다. 단순 쇼핑몰·SNS·블로그·AI 챗봇 중 하나로 축소하지 않는다.

이 순환의 구체적 장치:
- 도안 상세의 **공개 니팅로그 수·리뷰 수**가 "실제로 이걸 뜬 사람이 있다"를 보여준다.
- **게이지 조정 요약**(`품 +5cm · 소매 -3cm`)이 다음 구매자에게 "이 사람은 이렇게 사이즈를 바꿨구나"를 전달한다.
- **도안 문의**가 구매 전 궁금증을 판매자와 직접 해소한다.

## 2. 서비스 구조와 명칭

```text
나의 뜨개방
├─ 기록
│  ├─ 코잇기
│  │  └─ 도안 타래
│  │     └─ 니팅로그
│  │        └─ 오늘의 로그
│  └─ 실타래
└─ 내 활동
   ├─ 좋아요 로그
   ├─ 팔로우 계정
   ├─ 내 리뷰
   └─ 포인트
```

| 사용자 화면 | 내부 명칭 | 비고 |
|---|---|---|
| 나의 뜨개방 | 개인 기록·활동 영역 | |
| 코잇기 | 도안별 니팅로그 그룹 조회 | `/coitgi`, `/projects` |
| 도안 타래 | **테이블 아님.** 연결 도안 기준 자동 그룹 | |
| 니팅로그 | `KNITTING_PROJECT` | `/projects/[id]` |
| 오늘의 로그 | `CONTENT_POST` 중 `PROJECT_LOG` | |
| 실타래 | `CONTENT_POST` 중 `FREE_POST` | |
| 도안 리뷰 | `PATTERN_REVIEW` — 도안에 속한 독립 게시물 | |
| 도안 문의 | `PATTERN_INQUIRY` — 도안에 속한 질문/답변 | **v2 신규** |
| 포인트 | `POINT_TRANSACTION` 거래 내역과 파생 잔액 | |

사용자는 도안을 먼저 생성하지 않는다. `니팅로그 생성 → 도안 연결 → 도안 타래 자동 구성 → 오늘의 로그 작성` 순서다. 같은 도안으로 여러 니팅로그를 만들 수 있다.

## 3. 회원·인증 ※ v2 확장

### 이메일 가입·로그인
- 이메일·비밀번호로 가입/로그인한다. 웹 인증은 **서버 세션 + HttpOnly·Secure·SameSite 쿠키**를 사용한다.
- 상태 변경 요청은 **CSRF 보호**를 적용한다(쿠키 `XSRF-TOKEN` → 헤더 `X-XSRF-TOKEN`).
- 가입 시 **약관 동의 내역을 버전과 함께 저장**한다: 서비스(필수)·개인정보(필수)·마케팅(선택). 약관 버전은 `1.0`.

### 카카오 소셜 로그인 ✅ v2 신규
- 카카오 간편 로그인을 제공한다(수동 인가코드 흐름). 카카오 키가 설정돼 있을 때만 로그인 버튼을 노출한다.
- **신규 소셜 회원**은 곧바로 가입되지 않고 **개인정보 동의 단계**를 거친다.
  - 콜백 결과가 기존 연결이면 즉시 로그인(`LOGGED_IN`), 신규면 동의 필요(`CONSENT_REQUIRED`) 상태로 임시 티켓을 발급한다(TTL 10분).
  - 동의 완료 화면에서 닉네임 확인 + 필수 약관(서비스·개인정보) 동의 후 계정을 생성하고 로그인한다.
- 소셜 회원은 **비밀번호가 없다**(로그인 비밀번호 없이 카카오로만 로그인). 이메일은 카카오에서 미제공일 수 있으므로 **없을 수 있다.**
- 같은 카카오 계정이 두 회원에 붙지 않도록 `(provider, provider_uid)`를 유니크로 강제한다.
- 닉네임은 카카오 프로필에서 유추하되 빈값이면 `코잇러`, 중복이면 숫자 접미(최후 UUID)로 자동 해소한다.

### 역할
- 한 계정이 `USER`·`SELLER`·`ADMIN`을 **동시에** 가질 수 있다. 배타적 단일 값이 아니다. 판매자로 승인돼도 일반 사용자 기능을 그대로 쓴다.

### 탈퇴
- 사용자 행을 삭제하지 않는다. 이메일·비밀번호·프로필 이미지 등 **인증·식별 정보를 파기**하고 상태를 탈퇴로 바꾼다.
- **닉네임은 유지·재사용 차단**한다(과거 글 작성자 표시 연속성).
- 탈퇴 사용자의 공개 콘텐츠·리뷰는 유지하되 공개 사용자 홈 진입은 차단한다.

## 4. 도안 연결

니팅로그 생성 시 다음 중 하나를 선택한다.

| 구분 | 도안 파일 | 원작 실·바늘·게이지 | 입력 주체 |
|---|---|---|---|
| 구매 도안 | 열람 가능 | 자동 불러오기 | 판매자 |
| 판매 도안 | 열람 불가 | 자동 불러오기 | 판매자 |
| 외부 도안 | 저장하지 않음 | 없음 | 사용자 |

### 원작 정보 스냅샷
구매·판매 도안의 원작 실·바늘·게이지·**사이즈**는 **연결 시점 값을 복사해 저장**한다. 판매자가 이후 도안 정보를 수정해도 이미 만들어진 니팅로그 값은 바뀌지 않는다. 연결 시점 도안 버전을 함께 저장하고, 이후 변경 내역을 니팅로그에 시간순으로 표시해 사용자가 스냅샷 갱신 여부를 선택한다.

외부 도안은 사용자 소유 데이터로 관리하며 스냅샷을 만들지 않는다. 유사한 이름만으로 자동 병합하지 않는다. **외부 도안의 PDF·도안 본문 이미지는 저장하지 않는다.**

## 5. 니팅로그와 오늘의 로그

- 니팅로그 제목은 선택 입력이며 미입력 시 날짜 기반 제목과 중복 순번을 사용한다. 도안 정보는 필수다.
- 실·바늘·게이지는 여러 행으로 입력한다. 자유 입력의 AI 구조화는 사용자가 확인·수정 후 저장하며, AI 실패 시 즉시 수기 입력으로 전환한다(⬜ AI 배선 미완).
- 대표 이미지는 최대 7개, 미등록 허용.
- 최초 상태는 `PLANNED`, 공개 기본값은 비공개.

### 상태
`PLANNED` 준비 중 / `CO` 코잡기 / `WIP` 뜨는 중 / `UFO` 잠시 멈춤 / `FO` 완성

**전이 순서를 강제하지 않는다.** 니팅로그의 현재 상태는 **기록일 기준 가장 최신 로그**의 상태를 따른다(로그 생성·수정·삭제 시 재계산, 로그 0개면 `PLANNED`).

### 오늘의 로그
- `오늘의 로그 작성하기` — 기본(빠른 사진·코멘트) / 상세하게 기록하기(TipTap 블록 에디터). 두 방식은 같은 데이터를 쓰는 다른 작성 경험이다.
- 첫 로그의 상태 기본 제안값은 `CO`, 이후는 니팅로그 현재 상태.
- 제목 미입력 시 `YYYY.MM.DD의 로그`(중복 순번). 목록은 기록일 순 정렬.

## 6. 공개 설정

니팅로그와 오늘의 로그는 각각 공개 설정을 가지되 연동된다.

- **상속** — 로그 공개 기본값은 상위 니팅로그 설정을 따른다.
- **상향 전파** — 비공개 니팅로그의 로그를 공개로 저장하면 니팅로그도 함께 공개(확인 후). 확인하지 않으면 로그를 비공개로 저장한다.
- **하향 전파** — 니팅로그를 비공개로 되돌리면 하위 로그도 함께 비공개. 영향 로그 수를 안내하고, 리뷰 공개 유지 여부는 별도로 선택받는다.

결과적으로 `니팅로그 비공개 + 공개 로그 존재` 조합은 발생하지 않는다(DB CHECK 제약으로 강제).

## 7. 도안 리뷰

리뷰는 오늘의 로그에 **연결**하지 않고 **로그 내용을 복사해 오거나 새로 작성하는 독립 게시물**이다. 소속은 니팅로그가 아니라 도안이다.

- 해당 도안 **구매자만** 작성. 미구매·외부 도안에서는 작성 불가.
- **도안·사용자당 1개**(DB 부분 유니크로 강제). 삭제 시 재작성 가능.
- 복사 이후 원본 로그와 리뷰는 서로 영향을 주지 않는다.
- 작성 시점 니팅로그 상태와 **게이지 조정 요약**을 함께 복사·저장한다. 목록에서 `UFO`는 제외, `FO` 우선 노출.
- 환불이 발생해도 리뷰는 삭제·비공개 처리하지 않는다.

## 8. 도안 문의 ※ v2 신규 ✅

도안 상세(리뷰 하단)에서 구매 전 사용자가 판매자에게 질문한다.

- **APPROVED 도안**에만 작성. 로그인 필요, 본문 최대 2000자.
- **공개/비공개** 선택. 비공개 문의는 **작성자·해당 도안 판매자·관리자만** 본문을 열람한다. 그 외에는 작성자 닉네임이 `비공개`로 마스킹되고 본문·답변이 가려진다.
- 판매자만 답변한다. 답변이 있으면 답변 시각·답변자를 함께 기록(부분 상태 방지).
- 별도 알림 인프라 대신 **판매자 문의함(미답변 폴링형 인박스)**과 미답변 수 배지로 제공한다.
- 작성자는 답변 전에만 수정 가능. 삭제는 작성자·관리자가 논리 삭제한다.

## 9. 포인트

리뷰 작성을 유도해 다음 구매자의 판단에 쓰일 실제 제작 정보를 확보하는 것이 목적이다.

- 리뷰 최초 등록 시 포인트를 지급(도안당 1회, **현재 500P — 정책 미확정**). 다른 도안 구매에 사용한다.
- 잔액은 **거래 내역 합계**로만 관리하고 음수가 되지 않는다.
- 리뷰 삭제 시 회수하되 잔액 부족이면 회수하지 않고 사유를 기록한다.
- 주문 취소·환불 시 사용 포인트를 반환한다.
- 사용 포인트는 **플랫폼이 부담**하며 판매자는 정가 기준으로 정산받는다.

지급 금액·유효기간·1회 사용 한도·최소 사용 단위는 미확정이다.

## 10. 실타래와 소셜

- 실타래는 니팅로그와 무관한 자유 글이며 모든 블록 기능을 사용한다. 도안 카드는 본문 표시용일 뿐 자동 연결하지 않는다.
- 공개 글은 비로그인도 계속 볼 수 있고 3개 열람 후 로그인 권유를 1회 표시한다.
- 좋아요·댓글·신고·팔로우는 계정 기준 중복을 DB 제약으로 막는다. 자기 자신 팔로우 불가.
- 댓글 금칙어를 서버에서 검사한다(⬜ 금칙어 사전 관리 미구현).
- 신고 3건 관리자 확인 대상, 10건 자동 숨김. 사용자 비공개와 관리자·자동 숨김은 **다른 상태**다.

## 11. 주문·구매 도안·PDF ※ v2 확장

- 초기에는 **데모 결제**로 전체 구매 흐름을 확인한다(주문 생성 → 결제 완료 처리 → 사용권 생성). Toss Payments 테스트 연동은 ⬜ 계획.
- **주문은 도안 1건 단위.** 장바구니·다건 결제는 제외.
- **이미 보유한 도안은 재구매 불가**(서버 차단, DB 부분 유니크). 환불로 회수된 도안은 재구매 가능.
- 구매 도안은 카테고리·도안명·구매일로 조회한다.

### 도안 PDF 다중 등록·다운로드 ✅ v2 신규
- 도안 1건에 **PDF 여러 개**를 등록한다. 대표 PDF(`current_file_id`) + 전체 목록(`pdf_file_ids`) 이원 구조.
- 다운로드는 **파일별로** 요청한다(`fileId` 지정, 미지정 시 대표). 응답 헤더 `X-Download-Remaining`으로 남은 횟수를 알린다.
- 파일명은 도안 제목 기반(특수문자 치환)으로 내려준다.
- 기본 10회 다운로드 후 일시 중단, 재인증 시 다음 10회 허용(재인증 상한 없음). 다운로드 이력을 저장한다.
- PDF 상단 저작권 안내와 페이지 배경 추적 표식(워터마크)은 ⬜ **미구현**(코드 주석 명시).

## 12. 도안 등록 ※ v2 확장

- 판매자는 도안 상세 정보를 **행 단위 구조 입력**으로 등록한다. 사이즈명·시작 콧수, 게이지(코·단·기준 크기·바늘)는 필수 계산 근거다.
- **상세 설명은 TipTap 블록 본문**(`description_document`)으로 저장하고, 검색·미리보기용 평문(`description`)을 함께 유지한다. ✅ v2 신규
- **뜨개 방식에 혼합(MIXED)** 추가(대바늘·코바늘 혼용). ✅ v2 신규
- 코바늘 등 게이지를 숫자로 표현하기 어려운 도안은 게이지 자유 텍스트를 허용하되, 이 경우 게이지 계산은 비활성화된다.
- 초안(DRAFT)과 상품은 같은 테이블(`draftId == patternId`), 상태로 구분한다. 미리보기 후 제출하면 검수(PENDING) 대상이 된다.

## 13. 게이지 계산 ✅ v2 구현 (AI 설명 제외)

니팅로그에서 게이지 계산을 실행한다(`/projects/[id]/gauge`).

- **1단계 — 게이지 보정**: 내 게이지 기준 조정 콧수·예상 완성 치수·도안 대비 차이·바늘 추천을 계산한다.
- **2단계 — 부위별 목표 치수 조정**: 가슴둘레·총장·소매길이 등 부위별 목표값에 필요한 콧수·단수를 **치수 기준**으로 계산한다(시작 콧수 비례 아님).
- 조정 요약(`품 +5cm · 소매 -3cm`)을 만들어 니팅로그·리뷰 목록에 노출한다.
- 계산식을 결과와 함께 저장해 사용자가 검산할 수 있다. 콧수·단수는 반올림, 무늬 반복 단위 자동 보정은 하지 않고 안내만 한다.
- 니팅로그당 **적용 계산 1건**(DB 부분 유니크). 계산 결과는 니팅로그 공개 설정을 따른다(별도 공개 컬럼 없음, 공개 니팅로그는 비로그인도 조회 가능).
- AI 사이즈 조절 제안(`/ai/gauge-advice`)은 ⬜ **미배선**. AI 실패와 무관하게 계산만으로 화면이 동작한다.

## 14. 데이터·AI 원칙

- 니팅로그·오늘의 로그는 휴지통 이동 후 최대 90일 보관 뒤 완전 삭제(배치).
- 법정 보존 데이터(계약·결제·공급)는 콘텐츠 휴지통과 분리.
- **게이지 계산·상태·통계·수수료·포인트는 코드가 처리**한다. AI는 자유 입력 구조화·설명·요약·추천만 보조하며, 모든 AI 결과는 사용자 확인 후 저장한다.
- 계산 결과는 서버가 보관하고 AI 요청에는 **계산 식별자만** 전달한다.
- 무료 모델 우선, 무료 등급에는 테스트 데이터만 전송. 유료 전환 시 월 5달러 하드 리밋(80% 경고, 100% AI만 중단). (⬜ AI Provider/예산 미구현)
