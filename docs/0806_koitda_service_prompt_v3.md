# 코잇다 서비스 프롬프트 v3

> 기존 서비스 기획 기준의 브랜드·문제 정의·Vision·Mission·Objective·JTBD·KPI는 유지한다. 아래 내용은 이후 확정된 사용자 경험과 정책을 반영한 최신 서비스 기준이며, 기존 문서의 `프로젝트`·`리뷰 연결` 관련 표현과 충돌하면 이 문서를 우선한다.

## v3 변경 요약

- 도안 리뷰를 오늘의 로그 연결 방식에서 **복사 기반 독립 게시물**로 변경했다.
- 리뷰는 구매자만 작성하며 도안당 1개다.
- 리뷰 작성 시 포인트를 지급하고 도안 구매에 사용한다.
- 로그 공개 기본값은 니팅로그 설정을 상속하고, 로그를 공개하면 니팅로그도 함께 공개된다.
- 니팅로그 상태는 기록일 기준 최신 로그를 따르며 전이 순서를 강제하지 않는다.
- 판매 도안 연결 시 원작 정보를 스냅샷으로 복사하고 이후 변경 내역을 표시한다.
- 주문은 단건이며 이미 보유한 도안은 재구매할 수 없다.

## 1. 서비스 정의

코잇다는 도안 탐색·구매, 실제 작품 계획, 제작 과정 기록, 완성 경험 공유를 하나의 흐름으로 연결하는 뜨개 통합 플랫폼이다.

핵심 경험은 다른 사람의 실제 제작 정보가 다음 사용자의 선택과 시작을 돕는 순환이다. 단순 쇼핑몰·SNS·블로그·AI 챗봇 중 하나로 축소하지 않는다.

## 2. 서비스 구조와 명칭

```text
나의 뜨개방
├─ 기록
│  ├─ 코잇기
│  │  └─ 도안 타래
│  │     └─ 니팅로그
│  │        └─ 오늘의 로그
│  └─ 실타래
└─ 내 활동
   ├─ 좋아요 로그
   ├─ 팔로우 계정
   ├─ 내 리뷰
   └─ 포인트
```

- `코잇기`: 사용자의 니팅로그를 연결 도안별로 묶어 보여주는 영역
- `도안 타래`: 별도 생성 대상이 아니라 연결 도안 기준으로 자동 구성되는 그룹
- `니팅로그`: 사용자가 뜨는 작품 하나의 제목·도안·재료·대표 이미지·비고·현재 상태를 관리하는 상위 기록 단위
- `오늘의 로그`: 니팅로그 안에서 날짜별 제작 과정과 상태를 기록하는 글
- `실타래`: 니팅로그와 무관하게 뜨개 일상·위시·정보 등을 작성하는 자유 글
- `도안 리뷰`: 구매한 도안에 작성하는 독립 게시물. 니팅로그가 아니라 도안에 속한다

사용자는 도안을 먼저 생성하지 않는다. `니팅로그 생성 → 도안 연결 → 도안 타래 자동 구성 → 오늘의 로그 작성` 순서다. 같은 도안으로 여러 니팅로그를 만들 수 있다.

## 3. 도안 연결

니팅로그 생성 시 다음 중 하나를 선택한다. 세 방식은 불러오는 정보의 범위가 다르다.

| 구분 | 도안 파일 | 원작 실·바늘·게이지 | 입력 주체 |
|---|---|---|---|
| 구매 도안 | 열람 가능 | 자동 불러오기 | 판매자 |
| 판매 도안 | 열람 불가 | 자동 불러오기 | 판매자 |
| 외부 도안 | 저장하지 않음 | 없음 | 사용자 |

구매 도안은 코잇다 구매 기록으로 검증하고, 판매 도안은 상세 화면의 원작 정보만 불러온다. 외부 도안은 사용자가 최소 도안명 또는 가제를 직접 입력하며 구매처·판매 URL·가격·구매일·원작자를 선택 입력한다. 이름이 비슷해도 자동 병합하지 않고 기존 항목 연결 여부를 사용자에게 안내한다.

### 원작 정보 스냅샷

구매 도안과 판매 도안의 원작 실·바늘·게이지·사이즈는 **연결 시점의 값을 복사해 저장**한다. 판매자가 이후 도안 정보를 수정해도 이미 만들어진 니팅로그의 값은 바뀌지 않는다.

대신 연결 시점 이후 발생한 변경 내역을 니팅로그에 시간순으로 표시한다.

```
2026.08.10 원작의 실 정보가 변경되었습니다: 삭스얀 → 메리노 DK
2026.09.02 원작의 게이지 정보가 변경되었습니다: 22코 30단 → 24코 32단
```

사용자는 이 안내를 보고 스냅샷을 최신 정보로 갱신할지 선택한다. 니팅로그는 그 시점의 제작 기록이므로 기본은 갱신하지 않는다.

## 4. 니팅로그

- 제목은 선택 입력이며 미입력 시 날짜 기반 제목과 중복 순번을 사용한다.
- 도안 정보는 필수다.
- 실·바늘·게이지는 여러 개 입력할 수 있다.
- 자유 입력을 AI가 구조화된 행으로 변환할 수 있지만 사용자가 확인·수정한 뒤 저장한다.
- AI 실패 시 즉시 수기 행 입력으로 전환한다.
- 대표 이미지는 최대 7개이며 미등록할 수 있다.
- 작품의 기본 코멘트를 위한 비고를 제공한다.
- 최초 상태는 `PLANNED`, 공개 기본값은 비공개다.

코잇기는 도안명, 원작자·판매자명, 니팅로그 제목을 통합 검색한다. 상태, 도안 구분, 의류 카테고리, 코바늘·대바늘, 니팅로그 등록일로 필터링한다.

한 도안에 니팅로그가 1개면 바로 상세 내용을 보여주고 2개 이상이면 해당 타래 안에 니팅로그 선택 목록을 보여준다.

### 상태

| 코드 | 화면 표시 |
|---|---|
| `PLANNED` | 준비 중 |
| `CO` | 코잡기 |
| `WIP` | 뜨는 중 |
| `UFO` | 잠시 멈춤 |
| `FO` | 완성 |

**전이 순서를 강제하지 않는다.** 뜨개는 풀고 다시 뜨는 것이 정상 작업이므로 `WIP → UFO → CO → WIP`처럼 되돌리는 기록도 허용한다. 서비스는 어떤 전이도 막지 않는다.

니팅로그의 현재 상태는 **기록일 기준 가장 최신 로그**의 상태를 따른다. 오늘 완성 로그를 쓴 뒤 어제 날짜로 뜨는 중 로그를 추가해도 니팅로그는 완성으로 유지된다.

몇 번 풀고 다시 시작했는지는 로그 상태 흐름으로 대략 파악할 수 있으나, 사용자가 같은 상태로 이어서 기록하면 구분되지 않는다. 정확한 횟수 추적은 서비스 목표가 아니므로 별도 입력을 요구하지 않는다.

## 5. 오늘의 로그

작성 버튼 명칭은 `오늘의 로그 작성하기`다.

- 기본 작성: 사진·짧은 코멘트를 빠르게 기록
- 상세하게 기록하기: 블로그·노션과 같은 블록 에디터 사용

두 방식은 별도 게시글 유형이 아니라 같은 오늘의 로그를 작성하는 서로 다른 화면 경험이다. 제목 미입력 시 `YYYY.MM.DD의 로그`로 표시한다.

**첫 로그의 상태 기본 제안값은 `CO`다.** 니팅로그를 만들고 처음 기록한다는 것은 실제로 뜨기 시작했다는 의미이기 때문이다. 두 번째 로그부터는 니팅로그의 현재 상태를 기본으로 제안한다. 어느 경우든 사용자가 변경할 수 있다.

대표 이미지 전용 등록 버튼은 두지 않는다. 본문 이미지가 있고 대표 이미지가 비어 있을 때 저장 과정에서 본문 이미지 중 선택하거나 비워두도록 확인한다.

로그 목록은 작성 순서가 아니라 기록일 순으로 정렬한다.

## 6. 공개 설정

니팅로그와 오늘의 로그는 각각 공개 설정을 가지되 서로 연동된다.

**상속** — 로그의 공개 기본값은 상위 니팅로그의 설정을 따른다. 니팅로그가 비공개면 로그도 비공개가 기본이고, 공개면 로그도 공개가 기본이다. 사용자는 저장 전에 바꿀 수 있다.

**상향 전파** — 비공개 니팅로그의 로그를 공개로 저장하면 니팅로그도 함께 공개된다. 저장 전에 사용자에게 안내하고 확인받는다. 확인하지 않으면 로그를 비공개로 저장한다.

로그만 공개하고 니팅로그를 숨기지 않는 이유는, 다른 사용자가 그 로그를 봤을 때 어떤 도안으로 무슨 실을 써서 떴는지 확인할 수 없으면 코잇다의 핵심 가치가 끊기기 때문이다.

**하향 전파** — 니팅로그를 공개에서 비공개로 되돌리면 하위 로그도 함께 비공개가 된다. 저장 전 영향받는 로그 수를 안내한다. 해당 니팅로그에서 작성된 도안 리뷰가 있으면 리뷰의 공개 유지 여부를 별도로 선택받는다.

결과적으로 `니팅로그 비공개 + 공개 로그 존재` 조합은 발생하지 않는다.

## 7. 도안 리뷰

리뷰는 오늘의 로그에 연결하는 방식이 아니라 **로그 내용을 복사해 오거나 새로 작성하는 독립 게시물**이다.

### 작성 흐름

도안 상세에 리뷰 작성 버튼을 노출한다. 구매자이면서 아직 리뷰를 쓰지 않은 경우에만 보인다.

```
리뷰 작성하기
├─ 오늘의 로그 불러오기 → 본문·이미지를 복사해 편집
└─ 새로 작성하기       → 빈 화면에서 직접 작성
```

불러오기 목록에는 해당 도안에 연결된 본인의 니팅로그 로그만 표시한다. 비공개 로그도 불러올 수 있으며, 불러온 뒤 리뷰의 공개 여부는 별도로 설정한다.

### 규칙

- 해당 도안을 구매한 사용자만 작성한다. 미구매 사용자와 외부 도안에서는 작성할 수 없다.
- 한 사용자는 한 도안에 리뷰를 1개만 작성한다.
- 복사 이후 원본 로그와 리뷰는 서로 영향을 주지 않는다. 원본을 수정·비공개·삭제해도 리뷰는 그대로 유지된다.
- 작성 시점의 니팅로그 상태를 함께 저장한다. 리뷰 목록에서 `UFO`는 제외하고 `FO`를 우선 노출한다.
- 리뷰를 삭제하면 도안당 1개 제한이 해제되어 다시 작성할 수 있다.
- 환불이 발생해도 리뷰는 삭제하거나 비공개 처리하지 않는다.
- 리뷰에도 좋아요·댓글·신고를 적용한다.

### 로그와 리뷰의 차이

| | 오늘의 로그 | 도안 리뷰 |
|---|---|---|
| 소속 | 니팅로그 | 도안 |
| 개수 | 제한 없음 | 도안·사용자당 1개 |
| 작성 자격 | 누구나 | 해당 도안 구매자 |
| 성격 | 진행 중 기록, 계속 변함 | 구매 판단 근거, 안정적 |
| 원본 연동 | — | 복사 후 독립 |

진행 기록과 구매 판단 정보는 수정 주기가 다르다. 연결 방식이면 로그를 고칠 때마다 리뷰 영향을 확인해야 하지만, 복사 방식이면 그 확인이 필요 없다.

도안 상세에는 공개 니팅로그 수와 리뷰 수를 함께 표시한다.

## 8. 포인트

리뷰 작성을 유도해 다음 구매자의 판단에 쓰일 실제 제작 정보를 확보하는 것이 목적이다.

- 리뷰를 최초 등록하면 포인트를 지급한다. 도안당 1회다.
- 지급받은 포인트는 다른 도안을 구매할 때 사용한다.
- 리뷰를 삭제하면 지급 포인트를 회수한다. 이미 사용해 잔액이 부족하면 회수하지 않고 사유를 기록한다. 잔액을 음수로 만들지 않는다.
- 주문 취소·환불 시 사용한 포인트를 반환한다.
- 사용 포인트는 플랫폼이 부담하며 판매자 정산액에 영향을 주지 않는다. 포인트로 구매해도 판매자는 정가 기준으로 정산받는다.
- 적립·사용·회수·소멸 내역을 마이페이지에서 조회한다.

지급 금액, 유효기간, 1회 사용 한도, 최소 사용 단위는 미확정이다.

## 9. 실타래와 소셜

실타래는 모든 블록 기능을 사용할 수 있다. 표·체크리스트·토글·링크·동영상·도안 카드 등을 자유롭게 넣는다. 도안 카드는 본문에 표시할 뿐 니팅로그·도안 타래·리뷰를 자동 연결하지 않는다.

공개 실타래 글은 비로그인 사용자도 계속 볼 수 있다. 3개 이상 본 뒤 로그인 권유를 표시하지만 열람을 막지 않는다. 댓글 수는 노출할 수 있으나 댓글 내용과 작성은 로그인 후 제공한다.

댓글 등록 시 금칙어 위치를 표시하고 타인을 존중하는 작성 안내와 함께 등록을 차단한다. 신고는 로그인 계정당 같은 대상에 한 번만 가능하다. 유효 신고 3건은 관리자 확인 대상으로, 10건은 자동 숨김 대상으로 처리한다.

사용자가 스스로 설정한 비공개와 신고·관리자에 의한 숨김은 서로 다른 상태다. 작성자가 공개 설정을 바꿔도 숨김은 해제되지 않으며 관리자만 해제할 수 있다.

## 10. 주문·구매 도안·PDF

- 초기에는 데모 결제로 전체 구매 흐름을 확인한다.
- 이후 Toss Payments 테스트 키로 승인·실패·취소·환불을 구현한다.
- **주문은 도안 1건 단위다.** 장바구니와 다건 결제는 초기 범위에서 제외한다.
- **이미 보유한 도안은 재구매할 수 없다.** 도안 상세에서 구매 버튼 대신 보유 표시와 구매 도안 이동을 제공한다.
- 환불로 사용권이 회수된 도안은 다시 구매할 수 있다.
- 구매 도안은 카테고리·도안명·구매일로 조회한다.
- 도안 파일 접근 전에 로그인 비밀번호와 별개의 도안 잠금을 해제한다.
- PDF 다운로드 기간은 제한하지 않는다.
- 기본 10회 다운로드 후 일시 중단하고 재인증 시 다음 10회를 허용한다. 재인증 횟수에는 상한을 두지 않는다.
- PDF 상단에 저작권 보호 안내를 표시한다.
- 각 페이지 배경에 마스킹 사용자 ID·다운로드 일시·추적 코드를 흐리게 삽입한다.
- 모든 다운로드·재인증 이력을 저장한다.
- 환불 시 다운로드 권한은 회수하되 기존 다운로드 이력과 작성된 리뷰는 보존한다.

## 11. 판매·정산

- 플랫폼 판매 수수료 초기값은 판매금액의 10%다.
- PG 결제 수수료는 플랫폼 수수료와 별도로 공제한다.
- PG 수수료율은 결제수단·계약별로 달라질 수 있어 주문 당시 값을 저장한다.
- 도안 등록은 상세 화면 미리보기 후 최종 제출한다.
- 도안 파일 변경 시 변경 요약과 구매자 알림 여부를 확인하며 기본값은 발송이다.
- 변경 요약은 구매자 알림과 니팅로그 변동사항 표시에 함께 사용한다. 판매자는 한 번만 입력한다.
- 실제 자동 본인·사업자 인증은 초기 데모 범위에서 제외한다.

## 12. 데이터·AI

- 니팅로그와 오늘의 로그는 휴지통 이동 후 최대 90일 보관한 뒤 완전 삭제한다.
- 계약·결제·공급 기록 등 법정 보존 데이터는 콘텐츠 휴지통 정책과 분리한다.
- 탈퇴 시 이메일·비밀번호·프로필 이미지 등 인증·식별 정보를 파기한다. 작성자 표시용 닉네임은 유지하고 재사용을 차단한다.
- 탈퇴 사용자가 작성한 공개 콘텐츠와 리뷰는 삭제하지 않고 유지한다. 공개 사용자 홈은 접근할 수 없다.
- 게이지 계산과 통계는 코드로 처리한다.
- AI는 자유 입력 구조화, 설명, 요약, 사이즈 판단·도안 변형 추천을 보조한다.
- 모든 AI 결과는 사용자가 확인·수정한 뒤 저장하거나 게시한다.
- 포트폴리오 단계는 무료 모델을 우선하고 무료로 불가능할 때 가장 저렴한 적합 모델을 사용한다.
- 무료 AI에는 실제 개인정보·비공개 데이터를 보내지 않는다.
- AI 실패·예산 초과 시에도 수기 기능과 핵심 서비스는 정상 동작한다.
