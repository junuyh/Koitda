# 코잇다 API 목록 v2.3

> 요구사항 정의서 v1.3과 ERD v1.3 기준의 개발용 API 계약이다. 내부 경로는 `projects`를 유지하고 사용자 화면에서는 `니팅로그`로 표시한다. 금액과 포인트는 정수이며 날짜·시간은 ISO 8601 형식으로 주고받는다.
> **통합본이다.** v2.2 전문에 v2.3 변경분(게이지 계산)을 반영했다.

## 0. 버전 이력

| 버전 | 주요 변경 |
|---|---|
| v2.1 | 멱등키, PG 수수료 스냅샷, 영향 조회 |
| v2.2 | 리뷰·포인트·알림 신설, 리뷰 연결 폐기, 계산 식별자 도입 |
| **v2.3** | **게이지 계산 6개 신설, 도안 등록 구조화 입력, 조정 요약 응답 추가** |

### v2.3 변경 요약

**신설 6개** — 게이지 기본값 조회, 계산, 계산 조회, 적용, 적용 계산 조회, 계산 이력
**수정 7개** — 니팅로그 상세·리뷰 목록·리뷰 상세·공개 프로필에 조정 요약 추가, 판매자 도안 등록·수정 구조화 입력
**오류 코드 3개 추가**

## 공통 규칙

- 세션 쿠키 인증을 사용하고 상태 변경 요청은 CSRF 보호를 적용한다.
- 목록 API는 `page`, `size`, `sort`를 공통 사용하며 응답은 `items`, `page`, `size`, `totalElements`, `totalPages`를 포함한다.
- 오류 응답은 `code`, `message`, `fieldErrors`, `traceId`를 사용한다.
- 결제 승인·취소·환불과 포인트 적립·사용은 `Idempotency-Key` 헤더를 필수로 받는다.
- 공개·삭제 영향이 있는 변경은 영향 조회 후 발급받은 `confirmationToken`을 요청에 포함한다.
- 한 계정이 여러 역할을 가질 수 있으므로 권한 검사는 역할 목록 포함 여부로 판정한다.

| 코드 | HTTP | 발생 |
|---|---|---|

## 도안 리뷰

> 리뷰는 오늘의 로그에 연결하지 않는다. 로그 본문을 복사해 만드는 독립 게시물이다.

| 기능 | API | 주요 요청 | 주요 응답 |
|---|---|---|---|
| 리뷰 목록 | `GET /api/v1/patterns/{patternId}/reviews` | 정렬, 페이지 | 리뷰 목록. UFO 제외, FO 우선. 작성자, 대표 이미지, 작성시점 상태, **게이지 조정 요약**, 좋아요·댓글 수 |
| 작성 가능 여부 | `GET /api/v1/patterns/{patternId}/reviews/eligibility` | 도안 ID | `canWrite`, `reason`, `myReviewId` |
| 불러올 로그 목록 | `GET /api/v1/patterns/{patternId}/reviewable-posts` | 페이지 | 해당 도안에 연결된 본인 니팅로그의 로그. 비공개 포함 |
| 리뷰 작성 | `POST /api/v1/patterns/{patternId}/reviews` | `sourcePostId`(선택), 제목, 블록 본문, 대표 이미지, 이미지 목록, 공개 여부 | 리뷰 ID, 복사된 본문, **복사된 조정 요약**, 적립 포인트, 갱신된 잔액 |
| 리뷰 상세 | `GET /api/v1/reviews/{reviewId}` | 리뷰 ID | 본문·작성자·작성시점 상태·**조정 요약**·공개·소셜 정보 |
| 리뷰 수정 | `PATCH /api/v1/reviews/{reviewId}` | 수정값 | 수정 결과 |
| 리뷰 삭제 | `DELETE /api/v1/reviews/{reviewId}` | 확인값 | 처리 결과, 포인트 회수 결과, 재작성 가능 안내 |
| 내 리뷰 | `GET /api/v1/users/me/reviews` | 정렬, 페이지 | 내가 쓴 리뷰 목록 |

**작성 시 서버 검증 순서**

1. 로그인 여부
2. `PATTERN_LIBRARY`에 회수되지 않은 구매 기록 존재 → 없으면 `PURCHASE_REQUIRED`
3. 삭제되지 않은 기존 리뷰 존재 → 있으면 `REVIEW_ALREADY_EXISTS`
4. `sourcePostId`가 있으면 본인 소유이고 해당 도안 니팅로그의 로그인지 확인
5. 본문·이미지 복사, 작성 시점 니팅로그 상태와 **게이지 조정 요약 복사**
6. 포인트 적립 (`Idempotency-Key`로 중복 방지)

`sourcePostId`·`sourceProjectId`는 기록용으로만 저장하고 참조 무결성을 걸지 않는다. 조정 요약도 복사이므로 원본 계산이 나중에 바뀌어도 리뷰는 작성 시점 그대로다.

## 게이지 계산 ※ v2.3 신설

| 기능 | API | 주요 요청 | 주요 응답 |
|---|---|---|---|
| **계산 기본값 조회** | `GET /api/v1/projects/{projectId}/gauge-defaults` | 니팅로그 ID | 도안 게이지, 사이즈 목록, 실측 항목 표시명, 내 게이지 기본값, `requiresManualInput` |
| **계산 실행** | `POST /api/v1/gauge/calculations` | `projectId`(필수), 도안 게이지, 내 게이지, 선택 사이즈, 부위별 목표 치수 | `calculationId`, 1단계 결과, 부위별 조정 결과, 바늘 추천, 계산식, 경고 |
| **계산 조회** | `GET /api/v1/gauge/calculations/{id}` | 계산 ID | 저장된 입력·결과 스냅샷 |
| **계산 적용** | `POST /api/v1/gauge/calculations/{id}/apply` | 계산 ID | 적용 결과. 이전 적용 자동 해제 |
| **적용 계산 조회** | `GET /api/v1/projects/{projectId}/gauge-calculation` | 니팅로그 ID | 적용 중인 계산 결과. **공개 니팅로그는 비로그인도 조회 가능** |
| **계산 이력** | `GET /api/v1/projects/{projectId}/gauge-calculations` | 페이지 | 계산 이력 목록 |
| 계산 설명·추천 | `POST /api/v1/ai/gauge-advice` | `calculationId`, 사용자 확인값, 데이터 등급 | `draftId`, Provider·모델, 사이즈 조절 제안, 주의 문구, 예상 비용 |

**`gauge-defaults` 응답**

```json
{
  "patternSource": "CATALOG",
  "requiresManualInput": false,
  "patternGauge": { "stitches": 22, "rows": 30, "needleSizeMm": 4.5 },
  "sizes": [
    { "label": "1 (S)", "castOnStitches": 132,
      "measurements": { "chestCm": 96, "lengthCm": 58, "sleeveLengthCm": 46 } },
    { "label": "2 (M)", "castOnStitches": 148,
      "measurements": { "chestCm": 106, "lengthCm": 60, "sleeveLengthCm": 47 } }
  ],
  "measurementLabels": {
    "chestCm": "가슴둘레", "lengthCm": "총장", "sleeveLengthCm": "소매길이"
  },
  "myGaugeSuggestions": [
    { "projectGaugeId": 12, "stitches": 24, "rows": 32, "measuredStage": "SWATCH" }
  ]
}
```

외부 도안이면 `requiresManualInput: true`로 응답하고 `patternGauge`·`sizes`를 비운다(GAUGE-003).

**계산 요청**

```json
{
  "projectId": 45,
  "patternGauge": { "stitches": 22, "rows": 30, "needleSizeMm": 4.5 },
  "myGauge": { "stitches": 24, "rows": 32 },
  "selectedSizeLabel": "2 (M)",
  "targetMeasurements": { "chestCm": 111, "sleeveLengthCm": 44 }
}
```

`targetMeasurements`는 **변경한 부위만** 보낸다. 미포함 항목은 도안 값을 사용한다(GAUGE-010).

**계산 응답**

```json
{
  "calculationId": 301,
  "gaugeAdjustment": {
    "adjustedCastOnStitches": 161,
    "estimatedMeasurements": { "chestCm": 98.3, "lengthCm": 56.3 },
    "differenceFromPattern": { "chestCm": -7.7, "lengthCm": -3.7 },
    "formula": "148 × (24 ÷ 22) = 161.45 → 161"
  },
  "sizeAdjustments": [
    { "key": "chestCm", "label": "가슴둘레", "patternValue": 106,
      "targetValue": 111, "differenceCm": 5, "requiredStitches": 266,
      "formula": "111 × 24 ÷ 10 = 266.4 → 266" }
  ],
  "needleRecommendation": {
    "direction": "LARGER", "suggestedMm": 5.5,
    "note": "참고값이며 스와치 확인이 필요합니다"
  },
  "adjustmentSummary": "품 +5cm · 소매 -3cm",
  "warnings": ["무늬 반복 단위를 확인하세요"]
}
```

> 계산은 서버 수식으로 처리한다. AI에는 `calculationId`만 전달하며 계산값을 클라이언트가 되돌려 보낼 수 없다(GAUGE-016).
> 2단계는 **치수 기준**으로 계산한다. 시작 콧수 비례로 하면 톱다운 요크 스웨터에서 품 조정이 나오지 않는다.

**주문 생성 서버 처리 순서**

1. 보유 여부 확인 → 있으면 `ALREADY_OWNED`
2. 사용 포인트가 잔액 이하인지 확인 → 초과 시 `INSUFFICIENT_POINT`
3. 실결제 금액 = 판매가 − 사용 포인트
4. 주문 생성, 포인트 사용 거래 기록
5. 결제 완료 후 사용권 생성

환불 시 포인트를 반환하고 사용권을 회수한다. **작성된 리뷰는 삭제하거나 비공개 처리하지 않는다.**

```json

  "adjustmentSummary": "품 +5cm · 소매 -3cm",
```

**니팅로그 비공개 전환 흐름**

```

PATCH /projects/{id}  { visibility: "PRIVATE", keepReviewPublic: true, confirmationToken: "..." }
  → { hiddenLogCount: 3, reviewVisibility: "PUBLIC" }
```

리뷰는 하향 전파 대상이 아니다. 게이지 계산은 니팅로그 공개 설정을 따르므로 별도 처리가 없다.
