# 코잇다 ERD v2

> 기준: 실제 Flyway 마이그레이션 V1~V16 (PostgreSQL). ERD v1.3에 v2 변경분(소셜 로그인, 도안 문의, PDF 다중, 도안 블록 본문, 카테고리 트리, 혼합 craft_type)을 통합했다.
> 물리 테이블명은 **소문자 단수**. `USER`는 예약어라 테이블명이 `users`다. 상태값은 `VARCHAR + CHECK`.

## 0. 버전 이력

| 버전 | 주요 변경 |
|---|---|
| v1.2 | 리뷰 독립 게시물화, 포인트, 역할 겸직, 관리자 숨김 분리, 원작 스냅샷 |
| v1.3 | 게이지 계산 본 저장소화, 부위별 치수 조정, 도안 JSON Schema 확정 |
| **v2** | **소셜 로그인(user_social_login), 도안 문의(pattern_inquiry), PDF 다중(pdf_file_ids), 도안 블록 본문(description_document), 카테고리 트리, craft_type MIXED** |

### v2 변경 요약 (마이그레이션 대응)

| 마이그레이션 | 대상 | 변경 |
|---|---|---|
| V11 | `selling_pattern` | `description_document JSONB` 추가 (TipTap 블록 본문, `description`은 평문 병행) |
| V12 | `pattern_category` | 카테고리 트리 시드(스키마 변경 없음) |
| V13 | `selling_pattern`, `external_pattern` | `craft_type` CHECK에 `MIXED` 추가 |
| V14 | `selling_pattern` | `pdf_file_ids JSONB` 추가 (대표 `current_file_id` + 목록 이원 구조) |
| V15 | **신규 `pattern_inquiry`** | 도안 문의(공개/비공개·답변·판매자 인박스) |
| V16 | **신규 `user_social_login`** | 카카오 소셜 로그인 연결 |

## 1. 공통 설계 원칙

v1.3과 동일(대리키 BIGSERIAL, 정수 금액, `NUMERIC(5,2)` 요율, `TIMESTAMPTZ` UTC, `deleted_at`+`purge_at` 2단 삭제, `VARCHAR`+`CHECK` 상태, 비정규화 카운터, 파일 메타만 저장, 개인정보 컬럼 암호화, 스냅샷 복사, 파생 후 캐시, 반올림 정책, 계산식 저장).

### 참조와 복사의 구분

| 대상 | 방식 |
|---|---|
| 니팅로그 → 도안 원작 정보 | 복사(`pattern_snapshot`) |
| 게이지 계산 → 도안·내 게이지 | 복사(`pattern_gauge`/`my_gauge`) |
| 리뷰 → 오늘의 로그 본문 | 복사(`content_document` + `gauge_adjustment_summary`) |
| 주문항목 → 가격·수수료율 | 복사(스냅샷 컬럼) |
| 니팅로그 → 도안 식별자 | 참조 |
| 니팅로그 → 구매 여부 | 참조(조인) |
| 게이지 계산 → 공개 여부 | 참조(니팅로그 `visibility` 상속) |
| **도안 문의 → 도안** | **참조(FK `pattern_id`)** |

### user_role
PK(user_id, role), CHECK role IN (`USER`,`SELLER`,`ADMIN`), FK → users ON DELETE CASCADE. JPA에서는 `User`의 `@ElementCollection`.

### user_social_login (소셜 로그인) ※ v2 신규 (V16)
| 컬럼 | 타입 | 제약 |
|---|---|---|
| id | BIGSERIAL | PK |
| user_id | BIGINT | FK → users |
| provider | VARCHAR(20) | CHECK IN (`KAKAO`) |
| provider_uid | VARCHAR(100) | 카카오 회원번호(문자열) |
| created_at | TIMESTAMPTZ | NOT NULL |

**제약** — `UNIQUE (provider, provider_uid)` : 같은 카카오 계정이 두 회원에 붙지 않는다. 이 유니크가 로그인 조회 인덱스도 겸한다. `INDEX (user_id)`로 한 회원의 연결 목록 조회.

> users를 오염시키지 않고 소셜 연결을 별도 테이블로 분리한다(다중 프로바이더 대비).

### terms_agreement (약관 동의)
| 컬럼 | 타입 |
|---|---|
| id | BIGSERIAL PK |
| user_id | BIGINT FK → users CASCADE |
| terms_type | VARCHAR(30) CHECK IN (`SERVICE`,`PRIVACY`,`MARKETING`,`SELLER`) |
| terms_version | VARCHAR(20) — 현재 `1.0` |
| is_agreed | BOOLEAN |
| agreed_at | TIMESTAMPTZ |

이메일 가입·카카오 완료 양쪽이 이 테이블에 동의 배열을 저장한다. 필수 약관 = `SERVICE`, `PRIVACY`.

### file_asset (파일)
id, uploader_id(FK→users, 순환 FK는 마지막 ALTER로 해소), usage_type CHECK IN (`PROFILE`,`PATTERN_IMAGE`,`PATTERN_PDF`,`PROJECT_IMAGE`,`POST_IMAGE`,`REVIEW_IMAGE`,`SELLER_EVIDENCE`), original_name, content_type, byte_size, storage_key, thumbnail_key, upload_status CHECK IN (`PENDING`,`COMPLETED`), created_at, deleted_at.

> **NOTIFICATION 테이블은 아직 없다**(알림 ⬜ 미구현). ERD v1.3의 알림 도메인은 계획 상태.

### pattern_category (카테고리) ※ v2 트리 시드 (V12)

### 4-1. 도안 JSON Schema (v1.3 유지)
`gauge_info` = { stitches, rows, swatchWidthCm, swatchHeightCm, needleSizeMm, stitchPattern?, afterBlocking? }. 필수: stitches·rows·swatchWidthCm·swatchHeightCm·needleSizeMm.
`size_info` = { sizes: [ { label(필수), castOnStitches(입력 시 양수), measurements(최소 1개) } ] }. 위반 시 앱이 `PATTERN_SIZE_SCHEMA_INVALID`(422) 반환.
> **코바늘 등**은 게이지를 자유 텍스트(`gauge.text`)로만 넣을 수 있고, 이 경우 게이지 계산이 비활성화된다.

### PDF 다중 구조 (v2)
- `current_file_id` = 대표(다운로드 기본). `pdf_file_ids`(JSONB) = 전체 목록.
- 등록 시 `pdfFileIds`가 있으면 그 목록, 없으면 단일 `pdfFileId`를 목록화. **대표 = 목록 첫 번째.**

### pattern_inquiry (도안 문의) ※ v2 신규 (V15)
| 컬럼 | 타입 | 비고 |
|---|---|---|
| id | BIGSERIAL PK | |
| pattern_id | BIGINT NOT NULL | FK → selling_pattern (참조) |
| user_id | BIGINT NOT NULL | FK → users (질문자) |
| is_private | BOOLEAN NOT NULL DEFAULT false | true = 작성자·판매자·관리자만 본문 열람 |
| content | TEXT NOT NULL | 질문 본문(최대 2000자, 앱 검증) |

> `SELLING_PATTERN_FILE`·`PATTERN_CHANGE_LOG`는 ERD v1.3 계획이나 ⬜ 미구현(도안 변경 이력·재검수 알림 미완). PDF 버전 관리는 현재 `pdf_file_ids`로 단순화.

## 5. 도메인 3 — 니팅로그·오늘의 로그

### knitting_project (니팅로그)
| 컬럼 | 요점 |
|---|---|
| selling_pattern_id / external_pattern_id | **XOR** |
| title / display_title / title_sequence | 미입력 시 날짜 기반 |
| status | 최신 로그 파생 캐시, CHECK 5종 |
| visibility | DEFAULT PRIVATE |
| public_log_count | 공개 로그 수 |
| pattern_snapshot | JSONB (사이즈별 시작 콧수·완성 실측 포함) |
| pattern_version_no / snapshot_at | 연결 시점 도안 버전·복사 시각 |
| note | 비고 |
| deleted_at / purge_at | 휴지통 90일 |

**제약** — XOR CHECK, status/visibility CHECK, `external_pattern_id IS NULL OR pattern_snapshot IS NULL`(외부 도안 스냅샷 금지), **`CHECK (visibility='PUBLIC' OR public_log_count=0)`** (비공개+공개 로그 조합 차단).

`external_pattern`: user_id 소유, UNIQUE 없음(자동 병합 금지), craft_type CHECK NULL/(CROCHET,KNIT,MIXED), **file_id 컬럼 없음**(외부 PDF 미저장).

재료 하위: `project_yarn` / `project_needle` / `project_gauge`(내 게이지 출처, measured_stage CHECK NULL/(SWATCH,BODY), input_source CHECK(MANUAL,AI)) / `project_image`(**CHECK sort_order 0~6**).

### content_post (오늘의 로그 + 실타래)
post_type CHECK(PROJECT_LOG,FREE_POST), project_id(PROJECT_LOG만), log_date, knitting_status, content_document(JSONB TipTap), content_text, cover_file_id, visibility, moderation_status CHECK 4종, like/comment/view_count, deleted_at, purge_at.
조합 CHECK: projectlog_has_project / freepost_no_project / freepost_no_status / projectlog_has_logdate.
노출 조건: `visibility='PUBLIC' AND moderation_status='NORMAL' AND deleted_at IS NULL`. **부분 인덱스** idx_post_project_log(project_id, log_date DESC, created_at DESC) `WHERE deleted_at IS NULL`.

## 6. 도메인 4 — 주문·결제·구매 도안

`customer_order`(order_no UNIQUE, total/used_point/payment_amount, order_status CHECK 5종), `order_item`(pattern_title_snapshot, unit_price, platform_fee_rate/amount, pg_fee_rate/amount, refund_amount, settlement_amount).

정산: `settlement = unit_price − floor(unit_price×platform_fee/100) − floor(unit_price×pg_fee/100) − refund`. `used_point`은 제외(플랫폼 부담).

### pattern_library (구매 도안)
user_id, pattern_id, order_item_id UNIQUE, download_count, download_limit DEFAULT 10, unlock_count, download_suspended_at, revoked_at.
**부분 유니크** `uq_library_active (user_id, pattern_id) WHERE revoked_at IS NULL` (재구매 차단). 환불 시 행 삭제 없이 `revoked_at`만 채운다.
> `PAYMENT_TRANSACTION`·`PAYMENT_REFUND`·다운로드 로그·정산 테이블은 ERD v1.3 계획. 현재는 데모 결제(주문→완료→사용권)만 구현, PG·워터마크·정산 배치는 ⬜.

## 7. 도메인 5 — 도안 리뷰·포인트

### pattern_review
user_id, pattern_id, library_id(구매 검증), **source_post_id·source_project_id (FK 아님, 복사 기록)**, content_document/text, cover_file_id, knitting_status(작성 시점 복사), **gauge_adjustment_summary VARCHAR(200)** (작성 시점 조정 요약 복사), visibility CHECK(PUBLIC,PRIVATE), moderation_status CHECK(NORMAL,HIDDEN), like/comment_count, deleted_at.
**부분 유니크** `uq_review_active (user_id, pattern_id) WHERE deleted_at IS NULL` (도안당 1리뷰).
리뷰 목록: `pattern_id AND visibility=PUBLIC AND moderation_status=NORMAL AND deleted_at IS NULL AND knitting_status<>'UFO' ORDER BY (knitting_status='FO') DESC, created_at DESC`. 환불 여부는 조건에 없음.
`review_image`: 파일 복제 없이 `file_id`만 공유.

### point_transaction
tx_type CHECK 5종, amount(부호 포함), balance_after(CHECK ≥ 0), reason_code(`REVIEW_CREATED`·`PATTERN_PURCHASE`·`REVIEW_DELETED`·`ORDER_CANCELED`), review_id, order_id, **idempotency_key UNIQUE**, fail_reason, expires_at.
**부분 유니크** `uq_point_earn_per_review (review_id) WHERE tx_type='EARN'` (리뷰당 1회 적립).
불변식: `users.point_balance = SUM(amount)`, `≥ 0`. 현재 적립액 **500P(하드코딩, 미확정)**.

### 계산 규칙(구현)
```
1단계: 조정 콧수 = 도안 castOn × (내 코수 ÷ 도안 코수)  [castOn 있을 때만]
        예상 치수 = 도안 값 × (내 게이지 ÷ 도안 게이지)   (폭=코수비, 길이=단수비)
        바늘 = 내 코수 > 도안 → LARGER(+0.5) / < → SMALLER(−0.5) / = → SAME
2단계: 필요 콧수/단수 = 목표 치수 × 내 게이지 ÷ 10  (치수 기준, 시작 콧수 비례 아님)
반올림: 콧수·단수 정수 HALF_UP, 치수 소수1, 계산식 소수2
경고: 게이지 차이 ≥10% 스와치 재확인 + 항상 '무늬 반복 단위 확인'
```
> AI 테이블(`AI_PROVIDER_CONFIG`·`AI_USAGE_LOG`·`AI_RESULT_DRAFT`·`AI_BUDGET_MONTHLY`)은 계획, 현재 ⬜ 미구현.

## 10. 갱신 규칙 (v1.3 유지)

- **니팅로그 상태**: 로그 생성·수정·삭제 시 기록일 기준 최신 로그의 knitting_status로 갱신. 로그 0개면 PLANNED. 상태 이력 테이블 없음.
- **공개 전파**: 상속(로그 기본값=니팅로그) / 상향(로그 PUBLIC→니팅로그 PUBLIC, 확인 없으면 로그 PRIVATE) / 하향(니팅로그 PRIVATE→하위 로그 PRIVATE, 영향 수 안내·confirmation). 게이지 계산은 전파 불필요.
- **게이지 적용**: unapply all → apply one (트랜잭션).
- **카운터**: public_log_count, public_project_count, wish_count, review_count, like/comment/view_count, point_balance.
