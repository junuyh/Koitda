# 코잇다 UI 가이드 v2

> 신규 문서. 실제 구현된 프론트엔드(`frontend/src`)에서 역추출한 디자인 시스템 기준이다. Tailwind v4(제로 설정) + 인라인 유틸리티에 의존하므로, 이 문서가 흩어진 규칙을 한곳에 모은 **단일 기준**이다.
> 상태: ✅ 구현됨 / 🟡 부분·비일관 / ⬜ 미정(확정 필요)

## 0. 스택과 원칙

| 항목 | 값 |
|---|---|
| 프레임워크 | Next.js 16 App Router · React 19 |
| 스타일 | **Tailwind CSS v4**(config 파일 없음, `@tailwindcss/postcss`) |
| 테마 소스 | `src/app/globals.css` (**디자인 토큰 유일 소스**) |
| 폰트 | `next/font/google` Geist Sans / Geist Mono |
| 서버 상태 | TanStack Query (전역 클라 상태 라이브러리 없음) |
| 폼 검증 | React Hook Form + Zod (현재 `/login`·`/signup`만) |
| 에디터 | TipTap 3 (`RichEditor`/`RichContent`, `.tiptap-content` 스타일) |

**원칙**
1. 색은 **CSS 변수 또는 Tailwind neutral 스케일**을 쓴다. 임의 hex를 컴포넌트에 흩지 않는다.
2. 액센트 색은 **`src/features/ui/accent.ts`의 확정 클래스 문자열**만 쓴다(Tailwind purge 때문에 동적 조합 금지).
3. 공통 입력·버튼은 **`src/components/form.tsx`의 `inputClass`·`buttonClass`**를 재사용한다.
4. 라이트/다크 모두 지원(`prefers-color-scheme`).

## 1. 디자인 토큰

### 1-1. 색상 (globals.css)
```css
:root        { --background:#ffffff; --foreground:#171717; }
@media (dark){ --background:#0a0a0a; --foreground:#ededed; }
```
- `--color-background`, `--color-foreground`로 Tailwind에 노출.
- 본문 기본색은 foreground, 배경은 background.

### 1-2. 중립 팔레트 (실사용)
UI 골격은 Tailwind `neutral` 스케일로 구성한다.
| 용도 | 클래스 |
|---|---|
| 본문 텍스트 | `text-neutral-900` / dark `text-neutral-100` |
| 보조 텍스트 | `text-neutral-500` |
| 경계선(강조) | `border-2 border-neutral-900` |
| 경계선(약) | `border border-neutral-200` |
| 카드 배경 | `bg-white` / dark `bg-neutral-900` |

> **디자인 톤: 볼드/뉴브루탈리즘 계열** — 진한 보더(`border-2 border-neutral-900`), 둥근 모서리(`rounded-full`, `rounded-2xl`), 명확한 대비.

### 1-3. 액센트 팔레트 (`features/ui/accent.ts`) ✅
- 6색: **amber, rose, sky, emerald, violet, orange**.
- 각 3변형: `solid`(강조 채움) / `soft`(옅은 배경) / `wash`(가장 옅은 배경).
- **seed(id) 기반 고정 선택** — 같은 카드/도안은 항상 같은 색. 다크모드 변형 포함.
- ⚠️ 반드시 파일에 나열된 **완성 클래스 문자열**만 사용(런타임 문자열 조합 금지 → purge에서 삭제됨).

### 1-4. 타이포그래피
| 역할 | 클래스(권장) |
|---|---|
| 페이지 제목 | `text-2xl font-bold` |
| 섹션 제목 | `text-lg font-semibold` |
| 본문 | `text-sm`~`text-base` |
| 캡션 | `text-xs text-neutral-500` |

- 폰트 변수: `--font-geist-sans`, `--font-geist-mono`, `antialiased`.
- 🟡 **알려진 불일치**: `globals.css`의 `body`가 `Arial, Helvetica`로 하드코딩되어 Geist 변수와 어긋난다. **확정 필요** — `body`를 `var(--font-geist-sans)`로 통일 권장.

### 1-5. 간격·모서리·그림자
- 간격: Tailwind 기본 스케일(`p-4`, `gap-3`, `space-y-4` 등). 별도 스케일 문서 없음 → Tailwind 기본을 표준으로 채택.
- 모서리: 버튼·아바타·칩 `rounded-full`, 카드·패널 `rounded-2xl`.
- 그림자: 진한 보더로 입체감을 주고 그림자는 최소화(뉴브루탈리즘 톤).

## 2. 레이아웃 — `AppShell` ✅

```
┌───────────────────────────────────────────┐
│ 상단바 (h-14, sticky, backdrop-blur)        │  로고 "코잇다"(amber-300 배지) · 유저 아바타
├──────────┬────────────────────────────────┤
│ 사이드바   │  메인 콘텐츠                     │
│ (w-60,    │                                │
│ 데스크톱,  │                                │
│ 접이식)    │                                │
└──────────┴────────────────────────────────┘
모바일: 사이드바 → 상단 아래 가로 스크롤 내비로 전환 (md: 분기)
```

- **내비 8메뉴**(role 필터): 도안 / 둘러보기 / 내 니팅로그 / 코잇기 / 구매 도안 / 마이페이지 / 판매[SELLER] / 심사[ADMIN].
- 로그인 상태: 유저 아바타(닉네임 첫 글자) + 로그아웃. 세션 유저는 `useQuery(["me"])`, 로그아웃 시 `setQueryData(["me"], null)`.
- `/login`·`/signup`은 셸 내비를 숨긴다.
- 반응형 기준: `md`(768px). 모바일 우선.

## 4. 폼·검증 규칙

- **Zod 스키마**: 현재 `features/auth/schemas.ts`만 존재(`signupSchema`·`loginSchema`).
  - signup: email, password(8~72), nickname(1~30), 서비스·개인정보 필수 동의(`refine v===true`), 마케팅 선택.
- `/login`·`/signup`만 RHF+`zodResolver` 사용. 나머지 폼(`PatternForm`, 게이지, 문의·리뷰)은 `useState` 제어 + **서버 검증(`ApiError.fieldErrors`)** 의존.
- 🟡 권장: 새 폼은 가능하면 Zod 스키마를 `features/{domain}/schemas.ts`에 추가해 클라 검증을 일관화.
- 에러 표시: `Field`가 `role="alert"`로 접근성 노출. 서버 `fieldErrors`를 필드에 매핑.

## 5. 데이터·상태 규칙

- 서버 상태는 전부 TanStack Query. `QueryClient` 기본옵션 `retry:false`, `refetchOnWindowFocus:false`.
- 쿼리키 컨벤션: `["me"]`, `["patterns", params]` 등 배열 첫 요소=도메인.
- 로컬 UI 상태만 `useState`. 전역 상태 라이브러리 도입 없음(불필요 시 추가 금지).
- API 호출은 `lib/api.ts`의 `apiFetch`만 사용(프리픽스·CSRF·세션 쿠키 자동 처리). 직접 `fetch`는 PDF blob 다운로드 등 예외만.

## 6. 접근성·반응형 기준

- 모바일·PC 반응형(`md` 분기) 필수. 사이드바↔가로 내비 전환.
- 키보드 접근성: 폼 에러 `role="alert"`, 버튼/링크는 시맨틱 태그.
- 색 대비: 진한 보더·neutral-900 텍스트로 대비 확보. 액센트는 배경(soft/wash) 위주로 사용해 대비 유지.
- 다크모드: 모든 신규 컴포넌트는 `dark:` 변형을 함께 지정(accent.ts는 이미 포함).

## 7. 콘텐츠·톤 규칙 (사용자 표기)

- **사용자 화면에 "프로젝트"라는 말을 쓰지 않는다.** 내부 경로 `projects`는 유지하되 표기는 "니팅로그".
- 상태 표기: 준비 중·코잡기·뜨는 중·잠시 멈춤·완성.
- 도안 문의 비공개 마스킹: 작성자 닉네임 `비공개`, 본문·답변 숨김.
- 약관 전문(`consentDocuments.tsx`)은 **데모용 표준 문구, 오픈 전 법무 검토 필요**(코드 주석 명시).
