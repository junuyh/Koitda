## 1. 공통 설계 원칙

| # | 원칙 | 이유 |
|---|---|---|
| 1 | PK는 `BIGSERIAL` 대리키 | 의미 있는 값이 바뀌어도 참조가 깨지지 않는다 |
| 2 | 금액·포인트는 정수 원 단위 | 부동소수점 반올림 오차 차단 |
| 3 | 요율은 `NUMERIC(5,2)` 퍼센트 (10.00 = 10%) | 소수점 수수료율 계약 대응 |
| 4 | 모든 시각은 `TIMESTAMPTZ`, UTC 저장 | 표시 시점에 지역 시간 변환 |
| 5 | 사용자 콘텐츠는 `deleted_at` + `purge_at` 2단 삭제 | 휴지통 90일과 완전 삭제 구분 |
| 6 | 상태값은 `VARCHAR` + `CHECK` 제약 | ENUM은 값 추가 시 마이그레이션 비용이 크다 |
| 7 | 목록 표시용 집계는 비정규화 카운터 | 목록 20건에 COUNT 40회가 도는 것을 막는다 |
| 8 | 파일은 `FILE_ASSET`에 메타데이터만 | DB에 바이너리를 넣지 않는다 |
| 9 | 개인정보·정산 계좌는 컬럼 암호화 | 백업·로그 유출 시 원문 노출 차단 |
| 10 | 주문 시점 값·연결 시점 값은 **스냅샷 복사** | 원본이 바뀌어도 과거 기록이 흔들리지 않는다 |
| 11 | 잔액·상태는 직접 저장하지 않고 **파생 후 캐시** | 진실의 출처를 하나로 유지한다 |
| 12 | 반올림은 **버림(floor)**, 콧수·단수는 반올림 | 수수료는 플랫폼이 아닌 쪽에 유리하게 |
| 13 | **계산식을 결과와 함께 저장** | 사용자가 검산할 수 있어야 신뢰가 생긴다 |

### 참조와 복사의 구분

| 대상 | 방식 | 이유 |
|---|---|---|
| 니팅로그 → 도안 원작 정보 | 복사 | 그 시점의 제작 기록 |
| 게이지 계산 → 도안·내 게이지 | 복사 | 계산 근거는 계산 시점에 고정 |
| 리뷰 → 오늘의 로그 본문 | 복사 | 진행 기록과 구매 판단 정보는 수정 주기가 다름 |
| 주문항목 → 가격·수수료율 | 복사 | 과거 정산 불변 |
| 니팅로그 → 도안 식별자 | 참조 | 도안 타래 그룹핑 기준 |
| 니팅로그 → 구매 여부 | 참조(조인) | 나중에 구매하면 자동 반영 |
| 계산 결과 → 공개 여부 | 참조(상위 상속) | 니팅로그 `visibility`를 따름 |

### 4-1. 도안 JSON Schema ※ v1.3 확정

PATTERN-011로 확정되었다. **v1.2의 미확정 항목이 해소되었다.** 게이지 계산이 도안 정보를 자동으로 불러오려면 판매자별 형식 차이가 없어야 한다.

**`gauge_info`**

```json
{
  "stitches": 22,
  "rows": 30,
  "swatchWidthCm": 10,
  "swatchHeightCm": 10,
  "needleSizeMm": 4.5,
  "stitchPattern": "메리야스뜨기",
  "afterBlocking": true
}
```

| 항목 | 필수 |
|---|---|
| `stitches`, `rows` | ✅ |
| `swatchWidthCm`, `swatchHeightCm` | ✅ (기본 10) |
| `needleSizeMm` | ✅ (바늘 추천에 필요) |
| 나머지 | 선택 |

**`size_info`**

```json
{
  "sizes": [
    {
      "label": "1 (S)",
      "castOnStitches": 132,
      "measurements": {
        "chestCm": 96, "lengthCm": 58, "sleeveLengthCm": 46, "shoulderCm": 38
      }
    },
    {
      "label": "2 (M)",
      "castOnStitches": 148,
      "measurements": { "chestCm": 106, "lengthCm": 60, "sleeveLengthCm": 47, "shoulderCm": 40 }
    }
  ]
}
```

| 항목 | 필수 |
|---|---|
| `label` | ✅ |
| `castOnStitches` | ✅ |
| `measurements` | ✅ 최소 1개 항목 |
| `measurements` 개별 키 | 자유. 의류는 권장 키 사용 |

**의류 카테고리 권장 키**

| 키 | 표시명 |
|---|---|
| `chestCm` | 가슴둘레 |
| `lengthCm` | 총장 |
| `sleeveLengthCm` | 소매길이 |
| `shoulderCm` | 어깨너비 |

키를 완전히 고정하지 않는 이유: 모자·가방·양말은 필요한 항목이 다르다. 다만 권장 키를 쓰지 않으면 **부위별 비교가 되지 않으므로**, `PATTERN_CATEGORY.recommended_measurement_keys`로 등록 화면에 기본 행을 제시한다.

저장 시 JSON Schema 검증을 적용하고 위반 시 `PATTERN_SIZE_SCHEMA_INVALID`로 거부한다.

### 5-1. pattern_snapshot 구조 ※ v1.3 확장

PROJECT-017. **사이즈별 시작 콧수와 완성 실측이 반드시 포함된다.** 게이지 계산의 기준이 되기 때문이다.

```json
{
  "title": "올드패션 가디건",
  "designerName": "OOO",
  "gauge": { "stitches": 22, "rows": 30, "needleSizeMm": 4.5 },
  "yarns":   [ { "brand": "...", "name": "...", "weight": "DK" } ],
  "needles": [ { "type": "KNIT", "sizeMm": 4.5, "lengthCm": 80 } ],
  "sizes": [
    { "label": "1 (S)", "castOnStitches": 132,
      "measurements": { "chestCm": 96, "lengthCm": 58, "sleeveLengthCm": 46 } },
    { "label": "2 (M)", "castOnStitches": 148,
      "measurements": { "chestCm": 106, "lengthCm": 60, "sleeveLengthCm": 47 } }
  ]
}
```

**도안 타래는 테이블이 아니다.**

```sql
SELECT COALESCE(sp.title, ep.title) AS pattern_title,
       COUNT(*) AS project_count
FROM knitting_project kp
LEFT JOIN selling_pattern  sp ON kp.selling_pattern_id  = sp.id
LEFT JOIN external_pattern ep ON kp.external_pattern_id = ep.id
WHERE kp.user_id = :userId AND kp.deleted_at IS NULL
GROUP BY kp.selling_pattern_id, kp.external_pattern_id;
```

**도안 구분(PROJECT-014) 판별** — 컬럼을 두지 않고 조인으로 파생한다.

```sql
CASE
  WHEN kp.external_pattern_id IS NOT NULL THEN 'EXTERNAL'
  WHEN pl.id IS NOT NULL                  THEN 'PURCHASED'
  ELSE 'CATALOG'
END

### 9-1. input_snapshot 구조

```

도안 정보를 **여기서 한 번 더 복사한다.** 니팅로그 스냅샷과 시점이 다르기 때문이다. 니팅로그는 연결 시점, 계산은 계산 시점이며 그 사이에 스냅샷을 갱신했을 수 있다.

### 9-2. result_snapshot 구조

```json
{
  "gaugeAdjustment": {
    "adjustedCastOnStitches": 161,
    "estimatedMeasurements": { "chestCm": 98.3, "lengthCm": 56.3 },
    "differenceFromPattern": { "chestCm": -7.7, "lengthCm": -3.7 },
    "formula": "148 × (24 ÷ 22) = 161.45 → 161"
  },

    { "key": "sleeveLengthCm", "label": "소매길이", "patternValue": 47,

  ],

    "direction": "LARGER", "suggestedMm": 5.5,
    "note": "참고값이며 스와치 확인이 필요합니다"
  },
  "warnings": ["무늬 반복 단위를 확인하세요"]
}
```

### 9-3. 계산 수식

**1단계 — 게이지 보정 (GAUGE-006~009)**

```
조정 콧수 = 도안 시작 콧수 × (내 게이지 코수 ÷ 도안 게이지 코수)   → 정수 반올림
예상 너비 = 도안 시작 콧수 ÷ 내 게이지 코수 × 10                  → 소수점 1자리
추천 호수 = 도안 바늘 mm + (내 게이지 코수 − 도안 게이지 코수) × 0.5
```

**2단계 — 부위별 목표 치수 (GAUGE-010~012)**

```
필요 콧수 = 목표 치수(cm) × 내 게이지 코수 ÷ 10   → 정수 반올림
필요 단수 = 목표 치수(cm) × 내 게이지 단수 ÷ 10   → 정수 반올림
```

> **시작 콧수 비례가 아니라 치수 기준이다.** 톱다운 요크 스웨터는 시작 콧수가 목둘레다. 가슴둘레 106cm 도안의 시작 콧수 148코에 비율을 곱해도 품 조정이 나오지 않는다. 치수 기준이면 부위와 무관하게 성립한다.

무늬 반복 단위 자동 보정은 하지 않는다. 도안마다 달라 오히려 틀린 값이 나온다. `warnings`로 안내만 한다.

| `AI_BUDGET_MONTHLY` | year_month PK, limit_amount, used_amount, warned_at, blocked_at | AI-005 |

**`AI_RESULT_DRAFT`가 필요한 이유** — AI-002의 "사용자 확인 후 저장" 흐름에서 확인 전 결과를 둘 곳이 필요하다. 세션에 두면 브라우저를 닫을 때 날아가고, 클라이언트가 보관하면 AI가 만들지 않은 값을 확정 API로 보낼 수 있다.

**AI에는 `calculationId`만 전달한다** (GAUGE-016). 계산값을 클라이언트가 되돌려 보내는 경로를 막는다.

## 10. 갱신 규칙

### 니팅로그 상태 (POST-007)

```sql
UPDATE knitting_project kp
SET status = (
  SELECT cp.knitting_status
  FROM content_post cp
  WHERE cp.project_id = kp.id
    AND cp.post_type = 'PROJECT_LOG'
    AND cp.deleted_at IS NULL
  ORDER BY cp.log_date DESC, cp.created_at DESC
  LIMIT 1
)
WHERE kp.id = :projectId;
```

- 로그 생성·수정·삭제·복구 시 실행한다.
- 결과가 기존 값과 같으면 갱신하지 않는다.
- 로그가 0개면 `PLANNED`로 되돌린다.
- **상태 이력 테이블을 만들지 않는다.** 로그 목록이 곧 상태 이력이다.

### 공개 설정 전파

| 규칙 | 처리 |
|---|---|
| **상속** (POST-010) | 로그 생성 시 `visibility` 기본값 = 상위 니팅로그 값 |
| **상향** (POST-011) | 로그를 `PUBLIC`으로 저장 → 니팅로그도 `PUBLIC`. 확인 없으면 로그를 `PRIVATE`로 저장 |
| **하향** (PROJECT-019) | 니팅로그를 `PRIVATE`로 변경 → 하위 로그 전부 `PRIVATE`. 영향 로그 수 안내 |
| 리뷰 | 전파 대상 아님. 하향 시 공개 유지 여부를 별도로 선택받음 |
| **게이지 계산** | **전파 불필요.** 조회 시 니팅로그 `visibility`를 참조 |

세 규칙 모두 트랜잭션 안에서 처리하고 `public_log_count`를 함께 갱신한다.

### 게이지 계산 적용 (GAUGE-013)

```sql
-- 트랜잭션 내
UPDATE gauge_calculation SET is_applied = false
 WHERE project_id = :projectId AND is_applied = true;
UPDATE gauge_calculation SET is_applied = true
 WHERE id = :calculationId;
```

이전 계산은 삭제하지 않고 `is_applied`만 내린다. 계산 이력이 남아 "처음엔 이렇게 계산했다가 바꿨구나"를 볼 수 있다.

### 카운터 갱신 시점

| 카운터 | 증감 이벤트 |
|---|---|
| `KNITTING_PROJECT.public_log_count` | 로그 공개 상태 변경·생성·삭제·복구 |
| `SELLING_PATTERN.public_project_count` | 니팅로그 공개 상태 변경·생성·삭제 |
| `SELLING_PATTERN.wish_count` | 위시 등록·해제 |
| `SELLING_PATTERN.review_count` | 리뷰 생성·삭제·공개 변경 |
| `CONTENT_POST.like_count` / `comment_count` | 좋아요·댓글 생성·삭제 |
| `*.view_count` | 조회 로그 적재 시 |
| `USER.point_balance` | 포인트 거래 생성 |
